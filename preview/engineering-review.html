Implementation direction · proposed, not shipped

Share the geometry tools. Keep each domain's meaning.

Circuit nets, P&ID services, floorplan objects and breadboard contacts are different models. They can share bounds, text measurement, stable scene identity and collision tests without being forced into one universal layout engine.

1 · Author intent

Exact components, ports, package members, circuit membership and physical orientation.

2 · Resolve meaning

Domain adapter resolves named connections and rejects unknown pins or ambiguous ownership.

3 · Place + route

Domain layout supplies ports, obstacles and label bounds to reusable geometry tools.

4 · Check + publish

Scene carries diagnostics and identities. The host displays partial results honestly.

Start with the reproduced errors

Fix DIP numbering, footprint pitch and pin markers together. Give Circuit an exact pin-count contract. Make Logic gate bodies opaque and route around symbol/label obstacles. These have concrete, inspectable failures now.

Acceptance: 8 physical pins agree with 8 resolved holes; no surplus pin tokens become a label; no unrelated wire crosses a gate body.

Add packages to P&ID

Reuse the existing grouping concepts from Network / UML where useful, but keep process connectivity separate. Authored member IDs determine a frame's bounds. Initially reject overlapping or nested packages clearly if they are not implemented.

Acceptance: rename IDs or reorder equipment and membership stays identical. Pipes cross a frame without clipping. Service styles preserve engineering line types.

Make linked views a host capability

Start with authored outlet IDs and a small circuit-membership map in the host. Expose those IDs consistently through the current renderers. The live experiment demonstrates selection without inventing a universal document model.

Acceptance: selecting either outlet occurrence highlights both; hiding electrical annotations leaves walls intact; source changes invalidate transient bindings. Durable edit reconciliation remains separate work.

Measure the final drawing

Check node/label intersections, false junctions, component coverage and text size at the intended viewport. A known partial remains visible as partial; the renderer must not silently change the user's circuit to make it prettier.

Acceptance: a deliberately disconnected feedback net remains flagged. Dense drawings explain why they need more space instead of shrinking silently.

How we prevent case-specific fixes
  • Run the same fixture with renamed IDs, reordered declarations and longer labels.
  • Add and remove one branch; verify that layout degrades gradually without discarding the topology.
  • Test sparse and dense circuits, feedback loops, multi-pin parts, and intentional no-connects.
  • Verify light, dark, grayscale and narrow viewport output. Junctions cannot depend on color alone.
  • For breadboards, test DIP-8 and DIP-14, opposite orientations, half/full boards and rail breaks. Never infer rail continuity from a colored stripe.
  • Keep the original DSL unchanged in regression fixtures. A corrected-intent fixture is a separate source with an explicit change list.
