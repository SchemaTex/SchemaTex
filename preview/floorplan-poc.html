Inspection 01

能放进去的楼梯，却要求负坐标

当前 at 0,0 指的是旋转前矩形的左上角。物体绕中心旋转后，可见 bounding box 跑出房间；validator 数学没错，坐标语义却违背直觉。

#103 transform mismatch#104 fit / fill

旋转后超出 0.38m

at 0,0 仍按旋转前矩形解释

Current DSL
furniture stairs-u S1 in pantry
  at 0,0 size 1.83x1.075 rotate 90
After · ships in 1.0.14

以最终 bounding box 居中 fit

rotate first → fit → place

Proposed DSL

  fit margin 0.05 rotate 90
Ship rulefit 保持 symbol 比例，先旋转，再把最终 bounding box 放入 room interior；不加入会拉坏符号的 fill。
Inspection 02

房间一变长，门窗 clearance 就漂了

百分比适合“放在墙中间”，不适合施工尺寸。这个案例把墙从 3.67m 拉长到 4.4m：旧百分比让门离墙角、窗离门的实际距离一起变化。

Inspection 03

所有墙都是 20cm，建筑总宽当然对不上

当前墙只是沿 room boundary 画出的固定色带。真实住宅的外墙、承重墙、隔墙厚度不同；如果仍把墙当作 room 的副产品，shared wall 的厚度和 dimension reference 都没有可靠归属。

Inspection 04

Rotate 不能把左手楼梯变成右手楼梯

U/L 型楼梯有 handedness，镜像与旋转是两种不同变换。split-level 又是另一种结构：中间 landing 同时接一段 UP 和一段 DN，不是给现有箭头写 both 就够。

#102 flip staircases#106 split-level stairs
Before · 1.0.13

四种 primitive，只有 rotate 和 UP/DN label

入口在错误一侧时，只能旋转整个楼梯；split-level 需要手工叠两个 symbol。

After · mixed 1.0.14 scope

mirror ships；split stair 不支持

左侧 mirror 由 production renderer 生成；右侧 split stair 只验证目标 geometry，尚未进入 catalog。

Canonical proposal

furniture stairs-split S2 in entry size 1.8x2.6
Split statusmirror x|y 是 1.0.14 的明确轴向 reflection；不使用 bare flip 或负 rotation。右侧的 stairs-split 仍只是需求示意，不进入 release。
Inspection 05

房间名固定居中，正好压在灯具上

旧 renderer 只取 room 最大矩形的中心。新 layout 不做不可预测的自由搜索，而是在中心附近测试一组固定候选点，选择离中心最近、与 symbol overlap 最少的位置。

#97 room label overlap
Before · 1.0.13

room label 与 ceiling light 共用中心

文字仍会绘制，但读者无法同时辨认 room name 和 electrical symbol。

After · ships in 1.0.14

layout 选择最低碰撞分数的位置

结果 deterministic；先不增加手动 keyword，真实使用证明自动 placement 不够时再设计 escape hatch。

Implemented rule候选点从中心向外稳定排序，评分考虑 furniture 与 door-swing sector；小房间自动切成只显示 room name 的 compact label，避免 area 行压墙。

1.0.14 解决 visual contract；不冒充 electrical domain model。

  1. 已完成 geometry contract：fit、opening offsets、wall segments、door clearance 和 label placement 已走 production pipeline。
